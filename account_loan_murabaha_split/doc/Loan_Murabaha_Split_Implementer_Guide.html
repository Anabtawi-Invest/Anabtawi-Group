Loan Murabaha Split

Module technical name: account_loan_murabaha_split
Odoo version: 19.0  |  Depends on: account_loans, analytic
Audience: Implementers / Functional consultants
Purpose: Document what this customization does and how to use it

1. What this module solves

Standard Odoo Enterprise Loans posts each installment as one journal entry that mixes principal and interest/murabaha on the short-term due account.

Anabtawi Islamic-loan practice often needs:

  • Loan liability opened manually at principal + murabaha (full amount).
  • Monthly due amount = full installment (payment).
  • Murabaha expense posted on a separate entry / separate liability account.
  • Optional analytic distribution and a custom journal item label (البيان / Label).

This module extends account.loan Confirm behavior when the option is enabled. When the option is disabled, standard Odoo loan posting remains, with optional analytic + label enhancements.

2. Installation

  1. Place the module folder account_loan_murabaha_split on the server addons path (e.g. Anabtawi-Group addons).
  2. Restart Odoo.
  3. Apps → Update Apps List.
  4. Search Loan Murabaha Split → Install / Upgrade.
Note: Requires Enterprise Loans (account_loans) and Analytic.

5. What happens on Confirm

5.1 Checkbox OFF — standard Odoo + enhancements

Creates the normal loan moves. Payment entry (3 lines):

AccountDebitCredit
Long TermPrincipal
Expense (murabaha expense)Interest
Short Term DuePayment (principal + interest)
  • Analytic: 100% on the Expense line only (if Analytic Account is set).
  • Label: if Label is set → all 3 lines become {Label} {entry date}.
  • Plus standard LT↔ST reclassification (principal of next 12 months) and its reversal.

5.2 Checkbox ON — Murabaha split mode

For each amortization line (except skipped dates), Confirm creates:

A) Principal & Interest entry — total = full payment

AccountDebitCredit
Long TermPayment (principal + interest)
Short Term DuePayment (principal + interest)

B) Murabaha entry (only if interest > 0)

AccountDebitCredit
ExpenseInterest
Murabaha Liability (selected)Interest

C) Reclassification LT → ST and D) Reversal next day

  • Amount = sum of payment (principal + interest) for the next 12 schedule lines (not principal-only, unlike standard Odoo).
  • Skipped on the last schedule line.
  • Analytic: 100% on both Murabaha entry lines (Expense + Murabaha Liability).
  • Label: if set → applied to both lines of (A) and both lines of (B), using each move’s accounting date.
Numeric example (one month)
Principal 4,409.649  |  Interest 303.651  |  Payment 4,713.300
Entry A total = 4,713.300  |  Entry B total = 303.651
Reclass amount = sum of next 12 payments

6. Posted vs Draft entries

On Confirm, all future schedule moves are created with auto_post = at_date. Only moves with date ≤ today are posted immediately. Later dates stay Draft until their date (then auto-post).

7. How implementers should use the module (checklist)

  1. Create / import amortization schedule (Compute or upload).
  2. Set standard accounts: Long Term, Short Term Due, Expense, Journal.
  3. Set Label under Asset Group (optional).
  4. Open Loan Settings:
    • Enable Separate Murabaha Entry for Islamic split posting.
    • Select Murabaha Liability Account.
    • Select Analytic Account if needed.
  5. Post the manual opening bank/loan/murabaha entry outside the loan wizard (if required by finance).
  6. Click Confirm.
  7. Review Posted Entries: payment, murabaha, reclass, reversal.
  8. When paying the bank installment manually, clear Due (and murabaha liability if still open per policy) against Bank for the full installment.

8. Changing an already confirmed loan

Generated moves are created at Confirm time. To regenerate with new options:

  1. Cancel or Set to Draft (standard loan actions reverse/unlink generated moves).
  2. Adjust checkbox / accounts / Label / Analytic.
  3. Confirm again.

9. Important warnings for implementers

  • If the opening entry already books total murabaha, review with Accounting whether monthly Murabaha expense posts would double-count interest. Account mapping must follow CoA policy.
  • In split mode, Long Term is reduced by full payment each month (aligned with loan opened at P+I).
  • Reclass in split mode also uses payment, not principal-only.
  • Odoo loan Outstanding Balance is still driven by schedule principal logic; GL balances follow the journal entries.
